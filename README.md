# sPOD-NN

Non-intrusive model order reduction of transport-dominated problems: a shifted POD
(sPOD) splits the snapshots into co-moving frames, and a neural network maps the
parameters `(t, mu)` to the frames' time amplitudes and shifts. This repository
turns the code of the paper into a tested Python package.

## Layout

| Folder | Content |
|---|---|
| `src/spodnn/` | The package: data generation (synthetic and wildfire solver), POD/sPOD decomposition, scaling, network (Lightning), sPOD-I interpolation, error metrics, the `spodnn` command |
| `configs/` | One YAML file per case defining its data (`synthetic`, `wildfire1d`, `wildfire2d`, `wildfire2d_ww`); `configs/decomposition/` the sPOD settings per case |
| `dvc.yaml`, `dvc.lock` | The data pipeline (generate, then decompose, per case) and the hashes of its current results |
| `data/` | Generated datasets and decompositions (zarr stores), versioned with DVC, never in git |
| `tests/` | pytest suite; `tests/golden/` holds reference values from the paper code |
| `scripts/make_golden.py` | Regenerates the reference values from `paper/` (needs the original Python 3.9 environment) |
| `paper/` | The paper's notebooks, helpers and trained weights; frozen reference, not modified |
| `sPOD/` | Vendored sPOD library, installed as `spod-vendored` (import `spod`), with small documented fixes |
| `DL-ROM/`, `WildlandFire_model/` | Original network code and wildland fire solver, kept for reference |

## Development

Requires [uv](https://docs.astral.sh/uv/). Python 3.12 and all dependencies come from `uv.lock`.

```bash
uv sync                          # create .venv from the lockfile
uv run pre-commit install        # run lint and format checks on every commit

uv run pytest                    # fast tests (~30 s); tests marked slow are skipped by default
uv run pytest -m ""              # all tests, including the sPOD runs (~2 min)

uv run ruff check                # lint
uv run ruff format               # format
```

Dependencies change only through `uv add` / `uv lock` and a committed `uv.lock`.

CI (GitHub Actions) runs the pre-commit hooks and the full test suite, slow tests
included, on every push and pull request. It never generates the real data: the
tests build tiny datasets of their own.

## Data and decomposition

Every dataset is defined by a config file and regenerated by one command; DVC
reruns only what changed and keeps every version outside git.

```bash
uv run dvc repro                 # generate and decompose every case that is out of date
uv run dvc status                # which stages are out of date, and why
uv run dvc pull                  # fetch the stored results instead of recomputing them
uv run dvc push                  # back up new results (then commit dvc.lock)
```

The two stages per case can also be run directly:

```bash
uv run spodnn generate configs/wildfire1d.yaml                  # -> data/wildfire1d.zarr
uv run spodnn decompose configs/decomposition/wildfire1d.yaml   # -> data/decomposition/wildfire1d.zarr
```

Both skip a case whose config, code and library versions are unchanged (`--force`
recomputes) and write atomically. Each store carries a manifest: the config and its
hash, the code hash, library versions, git commit, run times and a sha256 per array,
so a result always says how it was made (`spodnn.dataset.read_manifest`).

| Case | Generate | Decompose | Data + decomposition |
|---|---|---|---|
| synthetic | 3 s | 1 min | 11 MB |
| wildfire1d | 11 s | 5 min | 25 MB |
| wildfire2d | 2.5 min | 33 min | 314 MB |
| wildfire2d_ww | 1.7 min | 13 min | 234 MB |

Times on an Apple M1 laptop (16 GB); the 2D decompositions peak at about 9.5 GB of memory.
